## Held for Jack

1. **The star prompt's gates are far stricter than the fleet's.** `ReviewPromptTracker` needs 5 launches, 7 days since first open, 3 positive moments, 3 distinct days of use and a 120-day cooldown; the fleet rule is the 2nd launch and 30 days. I recommend running Rollout S here next, because most installs are gone before day 7 and so are never asked.
2. **Trial wording when intro-offer eligibility is unknown.** The doc comment on `isEligibleForIntroOffer` says unknown shows the trial, but `refreshIntroEligibility` stores RevenueCat's `.unknown` as ineligible. Which offer a failed lookup advertises is a trial decision (same as baseball's held PC1). I recommend matching the code to the comment (map `.unknown` to eligible), because Apple still decides at purchase time.
3. **Experiments and the sold offering.** Products always come from the `default` offering (`Offerings.paywallOffering`), while `trial_cta` is read from `current`. A wording test works as is: put `trial_cta` on the variant offering's metadata (the control offering needs nothing). An Experiment that changes products or prices would not reach the paywall until `paywallOffering` follows `current`, which is a paywall decision.
4. **Project file.** This machine has no XcodeGen, so `StatScout.xcodeproj` was not regenerated for the three new test files and `RemoteConfig.swift`. gh-sim regenerates on the runner; run `xcodegen generate` after pulling.
